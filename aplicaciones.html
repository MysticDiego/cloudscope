La nube tiene sentido cuando ayuda a resolver una necesidad. Explora algunos escenarios y los aspectos que conviene evaluar antes de adoptar un servicio.

CASO / 01Comercio electrónico

Una tienda recibe más visitas.

Durante una campaña, la demanda de una aplicación puede aumentar. Una arquitectura preparada para escalar puede ajustar sus recursos y reducirlos cuando pasa el pico.

Concepto conectado: elasticidad. Requiere configuración y seguimiento.

CASO / 02Desarrollo de software

Un equipo necesita probar su aplicación.

Puede preparar un entorno temporal o desplegar código en una plataforma administrada para realizar pruebas antes de publicar una versión.

Concepto conectado: IaaS o PaaS, según el control necesario.

CASO / 03Continuidad

Una organización protege sus archivos.

Puede diseñar una estrategia de respaldo con almacenamiento remoto y definir cómo recuperar la información si ocurre un incidente.

Concepto conectado: almacenamiento y recuperación. Es necesario probar la restauración.

CASO / 04Análisis de datos

Un proyecto procesa mucha información.

Puede solicitar capacidad para analizar un conjunto de datos sin adquirir toda la infraestructura que utilizará durante ese procesamiento.

Concepto conectado: recursos bajo demanda y consumo medido.

Aplicaciones de referencia: Google Cloud: casos de uso. Sobre respaldo: AWS: almacenamiento en la nube.

Una visión equilibrada

El valor también depende
de cómo se utiliza.

Adoptar la nube implica decisiones técnicas, operativas y de administración.

Posibilidades

  • Agilidad: disponer de recursos con menos pasos de adquisición física.
  • Adaptación: ajustar capacidad cuando cambia el uso.
  • Enfoque: delegar determinadas tareas y dedicar más atención al proyecto.

Aspectos que cuidar

  • Consumo: vigilar recursos y costos; la nube no garantiza ahorrar.
  • Conectividad: considerar la latencia y el acceso al servicio.
  • Dependencias: evaluar portabilidad, condiciones y posibilidades de migración.

Consulta: Google Cloud: características y posibilidades de Cloud Computing. Las consideraciones se deben evaluar en el contexto de cada proyecto.

Responsabilidad compartida

Delegar infraestructura
también exige decisiones.

El proveedor protege y mantiene determinadas partes del servicio. Tu organización conserva tareas que cambian según la solución utilizada: cuentas, permisos, datos y configuración, entre otras.

Por ejemplo, administrar una máquina virtual no implica las mismas tareas que utilizar una aplicación SaaS. Conviene revisar las condiciones y responsabilidades del servicio concreto.

Preguntas para empezar

  • ¿Quién puede acceder a la información?
  • ¿Qué configuración debe gestionar el equipo?
  • ¿Cómo se supervisará el consumo?
  • ¿Cómo se recuperarán los datos?

Estas preguntas ayudan a reconocer qué se debe investigar antes de utilizar un servicio.
